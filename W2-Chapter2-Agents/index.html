    2주차 — Chapter 2: Agents (Subagents)¶

    맞춤 서브에이전트로 작업을 분담하고 병렬화하기. 메인 대화가 파일 덤프로 오염되는 문제를 "격리 컨텍스트에서 일하고 요약만 돌려주는 워커"라는 구조로 해결하는 챕터입니다. 에이전트를 정의하고, 부르고, 패턴으로 조합하는 전 과정을 다룹니다.

    원본: Claude Code Deep Dive Workshop / Chapter 2 — Agents (Subagents) (9파트, 108 슬라이드)
    기준 버전: Claude Code v2.1.226 / 2026년 7월 교재 · 공식 문서 code.claude.com/docs 반영

    회고¶

    가장 크게 바뀐 생각은 "에이전트는 많을수록 좋다"는 편견이 깨진 것입니다. 잦은 왕복이 필요한 작업이나 한 줄짜리 초단발 작업은 메인이 직접 하는 게 더 빠릅니다. 에이전트는 "무거운 작업을 떼어내는 도구"지, "뭐든 다 나눠주는 도구"가 아닙니다.

    실습에서 가장 놀란 건 두 가지입니다.

    첫째, 자동 위임이 제가 만든 에이전트로 안 갔습니다. code-reviewer에 시점 문구까지 넣어 잘 설명해놨는데도, "코드 리뷰해줘"라고만 하니 그 에이전트는 한 번도 안 불려왔습니다. 대신 Claude Code에 이미 내장된 /code-review 스킬이 처리했습니다. 완전히 방치된 건 아니고, 제가 만든 에이전트가 아니라 다른 경로로 처리된 것입니다. 특정 에이전트를 꼭 쓰려면 이름을 직접 불러야 한다는 걸 이번에 실감했습니다.

    둘째, tools로 도구를 제한해도 완전히 안전하진 않습니다. Bash(git log:*)만 허용해뒀는데 전혀 다른 명령인 whoami를 시켰더니 그냥 실행됐습니다. 도구 자체를 막는 건 확실하지만, Bash 안에서 어떤 명령을 치는지는 tools가 못 지킵니다. 진짜 안전장치가 필요하면 PreToolUse 훅을 따로 걸어야 합니다.

    공식문서와 대조해보니 오류 2건, 사실이 바뀐 것 8건이 나왔습니다. 가장 눈에 띈 건 랩이 안내하는 jq '.summary' 명령인데, 실제 응답에는 그런 필드가 아예 없어서 그대로 따라 하면 에러가 납니다. 반대로 /agents 화면이 사라졌다는 것과 Task 도구가 Agent로 이름이 바뀐 건 교재 설명이 정확했습니다. 결론은 1주차 때와 같습니다 — 교재가 틀린 게 아니라, 그 뒤로 제품이 계속 바뀌었습니다.

    마지막으로, 부모 세션의 권한 모드(auto)가 생각보다 결과에 크게 영향을 줍니다. 같은 에이전트라도 부모가 default냐 acceptEdits냐에 따라 파일이 바뀌기도 하고 안 바뀌기도 했습니다. "거부됐는지"는 로그 한 줄만 보지 말고, 실제로 파일이 바뀌었는지까지 같이 확인해야 안전합니다.

    30초 요약¶

    Subagent는 메인 대화 안에서 무거운 작업을 대신 처리하는 격리 워커입니다 — 메인이 대량 파일을 직접 읽으면 컨텍스트가 오염되지만, Subagent에 위임하면 그 처리는 격리된 자식 컨텍스트에서 끝나고 메인에는 요약만 돌아옵니다. 정의는 YAML 프론트매터 + 시스템 프롬프트 본문으로 이루어진 마크다운 파일 한 장이고, 필수 필드는 name과 description 둘뿐입니다. 부르는 방법은 자연어로 제안하거나, @agent-이름으로 반드시 그 에이전트를 지목하거나, --agent 플래그로 세션 전체를 그 에이전트로 고정하는 세 단계입니다.

    실전 패턴 5종은 읽기 전용 리뷰어, worktree 격리 테스터, 이중 잠금 보안 스캐너, skills 프리로드 문서 작성가, 4겹 방어 마이그레이션 봇입니다. 실습 환경·버전·권한 모드에 관한 세부사항은 아래 "시작하기 전에 확인할 것"과 실습 기록을 참고하세요.

    시작하기 전에 확인할 것¶

    Chapter 2는 Chapter 1(Claude Code 기본 사용법)을 전제합니다.

    가장 먼저 확인할 것은 claude --version이 2.1.198 이상인지입니다. 이 버전부터 Background 실행이 기본값으로 바뀌고 /agents 위저드가 제거됐기 때문에, 이전 버전이라면 교재 내용과 다른 동작을 볼 수 있습니다. 이 정리는 v2.1.226 기준입니다.

    에이전트 실습은 ~/claude-lab/ch1 프로젝트를 이어서 씁니다. Ch1에서 만든 user-service-lab이 없다면 핸즈온랩 HTML의 Task 00 복구 스크립트로 재생성하면 됩니다. 복구 스크립트를 실행하면 버그 수정 커밋까지 포함된 Ch1 완료 상태가 만들어집니다.

    이 챕터 실습을 헤드리스(claude -p)로 진행한다면, --allowed-tools로 도구를 좁힐 때 Agent를 빼지 않도록 주의하세요. 비대화형에서는 권한 프롬프트를 띄울 수 없어 사전 승인 목록이 곧 실행 가능 범위가 됩니다. 다만 --allowed-tools를 아예 쓰지 않으면 이 문제 자체가 없습니다 — 이번 실습은 전부 그렇게 돌렸습니다. 단 위임 자체가 "정상 동작"한 건 @멘션·--agent처럼 명시적으로 지정한 경우뿐이었고, 이름 없이 자연어로 "코드 리뷰해줘"라고만 요청하면 커스텀 에이전트 대신 내장 스킬로 새는 경우가 관찰됐습니다 — 자세한 내용은 Part 07.

    실습 기록¶

    Note

    원본 교재 PDF는 랩을 Lab 1~4로 부르지만, 실제 수행은 별도로 제공되는 핸즈온랩 HTML의 Task 00~05 구성을 기준으로 삼았습니다 — 두 자산의 랩 체계 자체가 다릅니다(자세한 차이는 Part 07 Task 00 참고). PDF Lab 4가 다루는 메모리·Fork 실습은 개념 설명만 Part 2·3에 반영했고, 별도로 실습하지는 않았습니다.

    실행 환경: macOS 26.5.1 / Claude Code v2.1.226 / 부모 세션 권한 모드 auto(이 환경의 기본값)

    Lab 상태 핵심 발견
    Task 00 — 사전 준비 ✅ 완료 랩 자산은 PDF 경로가 아니라 ccw-hands-on-lab/*.html에 있음
    Task 01 — 첫 Subagent(code-reviewer) ✅ 완료 Agent 도구·트랜스크립트 경로 확인. auto 모드에서 Bash 패턴 밖 명령(node test.js)이 거부 없이 실행됨
    추가 실험 — 권한 경계 측정 ✅ 완료 tools의 Bash(패턴)은 하드 울타리가 아님 (whoami 통과, 거부 0건)
    Task 02 — 도구 권한 격리 ✅ 완료 자연어·@멘션 둘 다 서브에이전트가 스스로 "Edit 권한 없음"을 보고. A/B 대조로 tools/권한모드가 별개 관문임을 확인
    Task 03 — 에이전트 3종 완성 ✅ 완료 타입어헤드는 대화형 전용이라 병렬 실행으로 대체 검증
    Task 04 — 디스패치 3패턴 ✅ 완료 자동 디스패치는 내장 /code-review 스킬로 우회, 명시 호출·병렬은 정상. 병렬 비용 $0.6256(3-agent)
    Task 05 — Headless와 CI ✅ 완료(랩 명령 오류 발견) 랩의 jq '.summary'·.issues가 JSON 응답에 없는 필드
    백그라운드 패널 조작 ✅ 완료 tmux 대화형 세션에서 관리 패널 진입·조작 확인
    /cost 서브에이전트 사용 비중 ✅ 완료 Subagents % of usage에서 개별 에이전트 비중 확인

    전체 로그와 원본 출력, 세션 ID는 → Part 07 — Recap & Labs
