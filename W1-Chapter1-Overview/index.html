    1주차 — Chapter 1: Overview¶

    Claude Code를 한 번도 써본 적 없는 사람이 이 문서만 읽고 "이게 뭔지 설명할 수 있고, 내 노트북에 깔아서 첫 세션을 돌릴 수 있는" 상태가 되는 것을 목표로 썼습니다.

    원본: Claude Code Deep Dive Workshop / Chapter 1 — Overview (10 파트, 약 190 슬라이드) 기준 버전: Claude Code v2.1 / 2026년 7월 · 공식 문서 code.claude.com/docs 반영

    회고¶

    Chapter 1은 Claude Code의 정체성부터 설치·인증·핵심 도구·워크플로 패턴까지를 훑는 입문 챕터입니다. 분량은 많지만 어려운 개념은 없어서, 오히려 "이미 아는 것 같은데 실은 모르는 것" 이 걸리는 챕터였습니다.

    정리하면서 가장 크게 바뀐 생각은 두 가지입니다.

    하나는 Claude Code를 "터미널에서 쓰는 자동완성"으로 이해하면 절반도 못 쓴다는 것입니다. 차이는 범위(파일 vs 저장소)보다 책임에 있었습니다. 자동완성은 제안까지가 끝이지만 Claude Code는 테스트를 돌려 스스로 검증합니다. 그래서 좋은 지시는 "무엇을 해라"가 아니라 "무엇이 완료인지" 를 함께 주는 것이더군요.

    다른 하나는 문서를 읽는 것과 직접 돌려보는 것의 간극입니다. 예상과 다른 지점이 계속 나왔습니다. 제 설치가 Native가 아니라 npm 경로였다는 것도 claude doctor를 돌리고서야 알았습니다. 디버깅 랩에서는 교재가 Grep으로 영향 범위를 검색할 거라고 예고했는데 실제로는 Grep을 쓰지 않았습니다. 파일이 네 개뿐이라 전부 읽는 게 빨랐던 겁니다. 교재 흐름도가 틀린 게 아니라 상황에 따라 도구 선택이 달라진다는 걸 눈으로 본 셈입니다.

    가장 인상적이었던 건 Plan 모드였습니다. soft delete 기능을 요청하면서 "getUser와 getUserPlan이 삭제된 사용자를 제외해야 한다"고 명시했는데, 계획을 보니 getUserPlan은 고칠 필요가 없다고 반박해 왔습니다. 직전 랩에서 이미 ?. 체이닝을 넣었기 때문에 getUser만 고치면 자동으로 충족된다는 것이었습니다. 액면 그대로 구현했다면 중복 방어가 들어갔을 겁니다.

    테스트 파일을 분리해 달라고 했을 때도, 제가 몰랐던 이유를 덧붙였습니다. 삭제 테스트가 전역 배열을 변경하는데 파일을 나누면 별도 프로세스로 실행되어 오염이 원천 차단된다는 것이었습니다. 저는 그냥 정리 차원에서 요청한 것이었는데 말이죠. 계획을 협상하면 버그를 코드가 아니라 문서에서 잡는다는 걸 체감했습니다.

    작성을 마친 뒤 교재 PDF와 공식 문서를 전수 대조했는데, 교재가 2026년 7월판이라 v2.1.207 전후로 바뀐 사실이 여럿 있었습니다. Bedrock의 opus alias가 4.6에서 4.8로 바뀐 것, 자동 업데이트가 Native 전용이 아니라는 것 등입니다. 특히 후자는 제 실습 로그가 이미 반증하고 있었는데도 본문 주장을 고치지 않고 넘어갔던 것이라 뼈아팠습니다. 관찰과 결론이 어긋나는지 따로 확인하는 절차가 필요하다는 걸 배웠습니다.

    마지막으로 하나 더. PDF에 적힌 실습 경로(ch1/lab3-buggy-app 등)가 저장소에 없어서 처음에는 "교재 자산이 빠졌다"고 판단하고 시나리오를 직접 재현했습니다. 그 판단이 틀렸습니다. 실습은 ccw-hands-on-lab/ 아래 HTML로 온전히 제공되고 있었고, 저장소에서 클론하는 대신 프로젝트를 직접 만들게 설계되어 있어서 애초에 그 디렉토리가 있을 이유가 없었습니다. 없는 걸 확인하는 데서 멈추지 말고 있을 만한 다른 곳을 먼저 찾았어야 했습니다. 지금은 HTML 랩의 원본 시나리오로 다시 수행한 기록으로 바꿔뒀습니다.

    30초 요약¶

    Claude Code는 터미널에서 도는 AI 코딩 에이전트입니다. 자동완성 도구와 다른 점은 딱 하나입니다.

    자동완성은 다음 몇 줄을 제안하고, Claude Code는 목표를 받아서 저장소 전체에서 작업을 끝냅니다.

    파일을 스스로 찾아 읽고, 고치고, 테스트를 돌려서 통과하는지 확인하고, 실패하면 다시 고칩니다. 이 "수집 → 실행 → 검증" 반복을 Agentic Loop라고 부르고, 이 루프를 돌 수 있게 모델 주위에 씌운 껍데기를 하네스(Harness) 라고 부릅니다. Chapter 1은 이 하네스가 무엇으로 이루어져 있고, 내가 그걸 어떻게 통제하는지를 다룹니다.

    시작하기 전에 확인할 것¶

    준비물은 생각보다 적습니다. 가장 자주 오해받는 것부터 짚겠습니다.

    Node.js는 필요 없습니다. 예전 자료를 보면 npm install이 나오지만 지금은 Native 설치가 표준이고, 단일 바이너리라 런타임 의존성이 없습니다. npm으로 설치할 때만 설치 시점에 Node 22+가 필요하며(v2.1.198 기준), 설치 후 실행에는 역시 Node를 쓰지 않습니다.

    계정은 하나 있어야 합니다. Claude 구독(Pro/Max/Team/Enterprise), Claude Console, AWS Bedrock 액세스 중 아무거나 하나면 됩니다.

    Warning

    Free 플랜에서는 Claude Code를 쓸 수 없습니다. 웹 채팅 전용입니다.

    OS와 하드웨어는 요즘 개발 머신이면 대체로 충족합니다. macOS 13 이상, Ubuntu 20.04·Debian 10·Alpine 3.19 이상, Windows 10 1809 이상을 지원하고, RAM 4GB에 x64 또는 ARM64면 됩니다. Apple Silicon은 네이티브로 돕니다.

    네트워크는 HTTPS 443으로 api.anthropic.com에 나갈 수 있어야 합니다. 사내 프록시와 커스텀 CA도 지원하므로 폐쇄망에서도 구성이 가능합니다.

    그 외에 Git, IDE(VS Code 또는 JetBrains), 익숙한 터미널이 있으면 좋습니다. 검색 엔진인 ripgrep은 설치 패키지에 기본 포함되어 있어 따로 깔 필요가 없습니다.

    실습 기록¶

    이 정리의 실습 부분은 읽고 옮긴 게 아니라 2026-08-02에 직접 실행한 결과입니다. 실행 환경: macOS 26.5.1 (Darwin 25.5.0, arm64) / Claude Code 2.1.220

    Lab 상태 핵심 발견
    Lab 1 — 설치와 첫 세션 ✅ 완료 claude doctor 결과 내 설치가 Native가 아닌 npm-global이었음
    Lab 2 — CLAUDE.md 만들기 ✅ 완료 도구를 0개만 허용해 자동 로드를 증명 (permission_denials: [])
    Lab 3 — 디버깅 ✅ 완료 교재는 Grep을 예고했지만 실제로는 안 썼음 — 4파일짜리라 전부 읽는 게 빨랐음
    Lab 4 — Plan 모드 ✅ 완료 계획 협상 재현. 요구사항 중 하나는 고칠 필요가 없다고 반박해 옴
    Lab 5 — Headless ✅ 완료 total_cost_usd가 JSON에 그대로 있음 / 입력의 99.99%가 캐시

    5개 랩 전부 수행했습니다.

    실습 자료 위치에 대하여

    PDF 슬라이드가 안내하는 ch1/lab3-buggy-app, ch1/lab4-todo-api 경로는 저장소에 실재하지 않습니다(전체 클론·전 브랜치 확인). 실제 실습은 ccw-hands-on-lab/ClaudeCode_Ch1_HandsOnLab.html 에 Task 1~7로 온전히 제공되며, 저장소에서 클론하는 대신 힙독으로 프로젝트를 직접 만드는 방식입니다. 구판(20260525) PDF와 스니펫 아카이브도 같은 방식이라, 경로를 지정한 건 신판 PDF뿐입니다. Lab 3·4는 이 HTML 랩의 원본 시나리오를 그대로 따라 수행했습니다.
