    Part 2 — 아키텍처¶

    한 줄 요약¶

    Claude Code는 모델을 감싼 하네스(Harness) 입니다. 도구, 컨텍스트 관리, 실행 환경을 제공해 그냥 텍스트를 만드는 언어 모델을 유능한 코딩 에이전트로 바꿉니다.

    왜 알아야 하나¶

    Part 1에서 "Agentic Loop가 돈다"고 했는데, 그 루프를 누가 돌리는지 아직 설명하지 않았습니다. 모델(Claude)은 사실 텍스트를 생성할 뿐입니다. "이 파일을 읽어라"라는 판단은 모델이 하지만, 실제로 디스크에서 파일을 읽어 오는 건 모델이 아닙니다. 그 일을 하는 게 하네스입니다.

    이 구분을 알아야 나중에 이런 질문에 답할 수 있습니다. - 왜 권한 승인 팝업이 뜨는가? → 하네스가 도구 실행 전에 권한을 검사하기 때문 - 왜 대화가 길어지면 요약되는가? → 하네스가 컨텍스트 윈도우를 관리하기 때문 - Bedrock으로 바꾸면 뭐가 달라지는가? → 하네스는 그대로고 Provider 계층만 바뀜

    개념 1 — 4계층 구조¶

    하네스(Harness)란? 원래는 말에 씌우는 마구(馬具)를 뜻합니다. 말(모델)의 힘을 실제 일에 쓸 수 있게 연결해주는 장치라는 비유입니다.

    ┌──────────────────────────────────────────────────────────────┐
│  Interface   Terminal CLI / VS Code / JetBrains /            │
│              Desktop / Web / Slack / CI                      │
│              → 동일 엔진의 여러 "표면"                          │
├──────────────────────────────────────────────────────────────┤
│  Harness     도구 실행, 권한 검사, 컨텍스트와 메모리 관리,        │
│              체크포인트, 세션 저장                              │
│              → Claude Code의 본체                             │
├──────────────────────────────────────────────────────────────┤
│  Model       Fable 5, Opus 4.8, Sonnet 5, Haiku 4.5          │
│              alias로 선택하고 /model로 전환                     │
├──────────────────────────────────────────────────────────────┤
│  Provider    Claude API / Amazon Bedrock / Google Vertex AI  │
│              / Microsoft Foundry / LLM Gateway               │
│              → 어디로 추론 요청을 보낼지 = 데이터 경계            │
└──────────────────────────────────────────────────────────────┘

    읽는 법: 위에서 아래로 요청이 흐릅니다. 내가 VS Code(Interface)에 프롬프트를 치면 → 하네스가 도구 결과와 컨텍스트를 모아 요청을 구성하고 → 선택된 모델로 → 설정된 공급자에게 보냅니다.

    가장 중요한 시사점: Interface를 바꿔도 하네스와 설정은 그대로입니다. 터미널에서 만든 CLAUDE.md가 VS Code에서도, Desktop 앱에서도 똑같이 적용됩니다.

    개념 2 — 실행 환경 3종 (인터페이스와 다른 축)¶

    인터페이스가 "내가 어디서 조작하는가"라면, 실행 환경은 "코드가 실제로 어디서 돌아가는가" 입니다. 이 둘은 다른 축입니다.

    환경 설명 관련 플래그
    Local 기본값. 내 머신에서 실행, 파일과 도구·환경에 완전 접근 —
    Cloud Anthropic 관리 VM에서 실행. 작업 오프로드, 원격 저장소 작업 --remote (터미널 → 클라우드)
    Remote Control 실행은 내 머신, 조작은 브라우저. 로컬 유지 + 웹 UI --teleport (웹 세션 → 터미널)

    Tip

    보안 심사를 통과해야 하는 조직이라면 이 구분이 핵심 질문입니다. "코드가 우리 망을 나가는가?"의 답이 여기서 갈립니다.

    Client Layer 상세¶

    인터페이스 특성 최적 용도
    Terminal CLI 전체 기능 기준점, 파이프와 스크립트 일상 작업, 자동화
    VS Code / Cursor 인라인 diff, @-mention, 플랜 검토 에디터 중심 개발
    JetBrains 대화형 diff, 선택 영역 컨텍스트 IntelliJ 계열 사용자
    Desktop App 병렬 세션, 예약 작업, Dispatch 멀티 세션 운영
    Web / iOS 클라우드 세션, 설치 불필요 원격, 이동 중 작업
    Slack / CI @Claude 멘션, Actions 통합 팀 협업, 파이프라인

    Agent SDK의 위치¶

    Agent SDK는 Claude Code의 하네스를 Python과 TypeScript 라이브러리로 노출한 것입니다. CLI가 쓰는 것과 동일한 도구·권한 체계를 내 앱에 내장할 수 있습니다.

    Claude Code CLI Agent SDK
    대화형 REPL과 헤드리스 모드 query() 등 프로그래밍 인터페이스
    사람이 주도하는 워크플로 앱과 서비스에 에이전트 내장
    설정은 settings.json 계층 도구, 권한, 훅을 코드로 제어
    설치만 하면 즉시 사용 (6주차 Chapter 6에서 심화)

    개념 3 — API 통신 경로와 인증 우선순위¶

    하네스는 설정된 공급자 하나로 추론 요청을 보냅니다. 환경변수 스위치로 경로를 선택하고, 조직은 게이트웨이로 중앙 집중할 수 있습니다.

    Claude Code ─┬─→ [PATH 1] Claude API            (기본, api.anthropic.com)
             ├─→ [PATH 2] Bedrock / Vertex / Foundry  (USE_BEDROCK 등 스위치)
             └─→ [PATH 3] LLM Gateway           (ANTHROPIC_BASE_URL, 조직 중앙 관문)

    인증 우선순위 6단계¶

    여러 자격증명이 동시에 존재할 때 무엇이 이기는가의 순서입니다. 실무에서 "왜 내가 설정한 키를 안 쓰지?"의 답이 여기 있습니다.

    순위 방식 설명
    1 Cloud Provider CLAUDE_CODE_USE_BEDROCK / VERTEX / FOUNDRY 설정 시 최우선
    2 AUTH_TOKEN ANTHROPIC_AUTH_TOKEN, Bearer 헤더로 전송, 게이트웨이 인증용
    3 API_KEY ANTHROPIC_API_KEY, X-Api-Key 헤더, 대화형에서는 1회 승인 필요
    4 apiKeyHelper 설정 스크립트가 반환하는 동적 키, 볼트 연동과 회전에 적합
    5 OAUTH_TOKEN claude setup-token으로 만든 1년 토큰, CI 파이프라인용
    6 /login OAuth 구독 사용자 기본값 (Pro / Max / Team / Enterprise)

    자세한 설정 방법은 Part 4 인증에서 다룹니다.

    Model Routing — 같은 alias, 다른 결과 (2026.07 기준)¶

    주의가 필요한 부분입니다. opus라고 써도 공급자마다 실제 모델이 다릅니다.

    공급자 opus가 가리키는 것 sonnet이 가리키는 것
    Claude API Opus 4.8 Sonnet 5
    Claude Platform on AWS Opus 4.7 Sonnet 4.6
    Bedrock / Vertex / Foundry Opus 4.6 Sonnet 4.5
    • 상위 모델을 쓰려면: 전체 모델명 또는 inference profile ARN을 직접 지정
    • alias 고정: ANTHROPIC_DEFAULT_OPUS_MODEL 등 환경변수로 alias가 가리킬 버전을 못박음
    • 조직 통제: availableModels 관리 설정으로 허용 목록을 만들면 picker와 플래그 모두 강제됨

    개념 4 — 도구 시스템 (Tool System)¶

    도구가 없으면 모델은 텍스트만 반환합니다. 도구가 있어야 읽고, 고치고, 실행하고, 검색하며 루프를 돌 수 있습니다.

    5가지 도구 카테고리¶

    # 카테고리 도구
    1 File Ops Read, Edit, Write, NotebookEdit
    2 Search Glob, Grep, 코드베이스 탐색
    3 Execution Bash, PowerShell, git, 테스트
    4 Web WebSearch, WebFetch, 문서 조회
    5 Code Intelligence LSP: 타입 오류, 정의 이동

    내장 도구 카탈로그¶

    도구 역할 승인
    Read / Edit / Write 파일 읽기, 정밀 수정, 신규 생성 Edit·Write는 승인 필요
    Glob / Grep 패턴 파일 찾기, 내용 정규식 검색 승인 불필요
    Bash / PowerShell 셸 명령 실행, Windows 네이티브 지원 승인 필요
    WebSearch / WebFetch 웹 검색과 URL 콘텐츠 조회 도메인 규칙 적용 가능
    Agent / SendMessage 서브에이전트 생성, 에이전트 간 메시지 (2주차 Chapter 2 심화)
    LSP / Monitor / Cron 코드 인텔리전스, 로그 감시, 예약 최근 추가된 도구

    2026년 상반기에 추가된 도구¶

    도구 능력
    LSP 편집 직후 타입 오류 확인, 정의 이동, 참조 찾기
    Monitor 백그라운드 명령 출력을 실시간 관찰하고 반응
    AskUserQuestion 요구사항이 모호할 때 객관식으로 사용자에게 질문
    Artifact 세션 결과를 조직 내 공유 가능한 라이브 페이지로 발행
    Cron 3종 세션 내 예약 도구
    RemoteTrigger Routines 백엔드
    EnterWorktree 격리 워크트리 진입
    ReportFindings 리뷰 결과 구조화

    Tip

    도구 이름 문자열은 그대로 재사용됩니다. 권한 규칙(Bash(npm test)), 서브에이전트의 tools 목록, Hook 매처에 동일한 이름이 들어갑니다. 그래서 정확한 이름을 외워두면 나중에 설정이 쉬워집니다.

    MCP — 외부 서비스를 도구로 연결¶

    MCP (Model Context Protocol) 는 AI 도구를 외부 데이터 소스에 연결하는 개방형 표준입니다. GitHub, Slack, 사내 시스템의 기능이 Claude의 도구로 등록됩니다.

    축 내용
    CONNECT claude mcp add로 stdio·HTTP 서버를 등록하고 /mcp로 상태 확인
    SCALE 도구 정의는 기본 지연 로딩 — 사용 시점에 온디맨드로 로드해 컨텍스트 절약
    AUTH claude mcp login으로 셸에서 OAuth 인증, 조직은 허용 목록 통제
    GOVERN managed 설정으로 서버 allowlist·denylist를 조직 차원에서 강제

    (MCP 심화는 4주차 Chapter 4)

    개념 5 — 권한 모델: 규칙과 모드의 이중 구조¶

    권한은 도구별 규칙과 세션 모드의 조합으로 결정됩니다. 규칙이 정적 정책이라면, 모드는 세션의 자율성 다이얼입니다.

    RULES (settings.json) MODES (Shift+Tab)
    allow: 묻지 않고 실행 Plan: 소스 수정 없이 계획
    ask: 실행 전 확인 Default: 편집과 명령마다 확인
    deny: 무조건 차단 Accept Edits: 파일 작업 자동
    Bash(npm test) 등 도구별 패턴 Auto: 백그라운드 안전 검사
    조직 managed 설정이 최우선 비대화 환경은 --permission-mode

    개념 6 — 컨텍스트 윈도우 관리¶

    세션 시작 시 무엇이 로드되는가¶

    # 세션 컨텍스트에 들어가는 것들
  System instructions      하네스 기본 지침
  CLAUDE.md (계층 병합)      프로젝트, 사용자, 조직 지침
  Auto memory (MEMORY.md)  첫 200줄 또는 25KB
  Skills 설명부             본문은 사용 시점 로드
  MCP 도구 이름              정의는 온디맨드 로드
  대화 이력 + 도구 출력       세션이 길수록 증가

    확인 명령: 

    > /context      # 사용량을 색상 그리드로 시각화
> /mcp          # 서버별 컨텍스트 비용 확인

    Context Compaction — 한계에 다가갈 때¶

    한계에 접근하면 오래된 도구 출력부터 정리하고, 필요하면 대화를 요약합니다.

    단계 동작
    STAGE 1 — 임계 감지 윈도우 사용량이 한계에 접근
    STAGE 2 — 출력 정리 오래된 도구 출력부터 제거
    STAGE 3 — 대화 요약 요청과 핵심 코드는 보존
    GUARD — Thrashing 방지 반복 실패 시 루프 대신 오류 표시

    중요

    초반에 준 세부 지시는 compaction 과정에서 사라질 수 있습니다. 그래서 세션 내내 지켜져야 하는 영속 규칙은 대화가 아니라 CLAUDE.md에 둡니다. (Part 8)

    개념 7 — Checkpointing: 모든 편집은 되돌릴 수 있다¶

    Claude가 파일을 편집하기 전에 해당 파일의 현재 내용을 스냅샷으로 남깁니다. Esc 두 번 또는 /rewind로 이전 상태로 되돌립니다.

    축 내용
    SNAPSHOT 영향받는 파일을 자동 스냅샷. git과는 별개의 세션 로컬 기록
    REWIND Esc Esc 또는 /rewind로 코드와 대화를 특정 시점으로 롤백. /clear 이전으로도 복귀 가능
    SCOPE 파일 변경 한정. DB, API 호출, 배포 등 외부 부작용은 미포함
    STORAGE ~/.claude/projects/ 아래 JSONL 평문 기록 → resume과 fork의 기반

    Warning

    체크포인트가 있다고 해서 아무거나 실행시켜도 안전한 게 아닙니다. 파일만 되돌아갑니다. terraform apply나 DROP TABLE은 되돌아가지 않습니다. 그래서 실행 전 확인이 여전히 필요합니다.

    개념 8 — 보안 아키텍처 4겹¶

    계층 이름 역할 시점
    1 Permissions allow/ask/deny 규칙과 4가지 모드로 행동 사전 통제 사전
    2 Sandboxing 샌드박스 Bash로 파일시스템과 네트워크를 격리 실행 사전 (반경 제한)
    3 Checkpoints 편집 전 스냅샷으로 사후 복구 경로 확보 사후
    4 Audit 세션 기록, Hooks, OpenTelemetry로 행위 추적과 정책 검증 감사

    네트워크 트래픽 패턴 (방화벽 규칙 설계용)¶

    목적지 용도 비고
    api.anthropic.com 모델 추론 요청, HTTPS 443 기본 경로
    claude.ai / downloads 로그인 콜백, 설치와 업데이트 설치 채널
    bedrock-runtime.*.amazonaws.com Bedrock 경로 추론 PrivateLink 가능
    MCP 서버 endpoint 등록한 서버별 상이 조직 allowlist 권장
    statsig / sentry 계열 기능 플래그, 오류 보고 환경변수로 비활성 가능

    현장 메모

    폐쇄망·프록시 환경 도입 검토 시 이 표가 그대로 방화벽 신청서가 됩니다. Bedrock 경로를 쓰면 api.anthropic.com 없이 AWS 계정 경계 안에서 처리되므로, 보안팀 설득이 훨씬 쉬워집니다.

    정리¶

    • Claude Code는 Interface / Harness / Model / Provider 4계층이고, 본체는 하네스입니다.
    • 실행 위치는 Local / Cloud / Remote Control 세 가지이며, 이게 데이터 경계를 결정합니다.
    • 인증은 6단계 우선순위로 충돌을 해석합니다. 클라우드 스위치가 가장 세고, 구독 OAuth가 가장 약합니다.
    • 도구는 5 카테고리 + MCP 확장이고, 도구 이름 문자열은 권한 규칙·훅에 그대로 재사용됩니다.
    • Compaction은 오래된 도구 출력부터 정리하므로, 영속 규칙은 CLAUDE.md에 둬야 합니다.
    • Checkpoint는 파일 변경만 되돌립니다. 외부 부작용은 대상이 아닙니다.
