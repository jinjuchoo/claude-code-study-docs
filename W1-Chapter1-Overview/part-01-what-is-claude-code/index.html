    Part 1 — Claude Code란 무엇인가¶

    한 줄 요약¶

    Claude Code는 코드베이스를 읽고, 파일을 편집하고, 명령을 실행하며 개발 도구와 통합되는 Anthropic의 Agentic Coding 도구입니다. 자연어 지시를 받아 여러 단계의 작업을 자율적으로 완수합니다.

    왜 알아야 하나¶

    "AI 코딩 도구"라는 말은 지금 너무 많은 걸 가리킵니다. GitHub Copilot도, Cursor도, ChatGPT에 코드 붙여넣는 것도 다 AI 코딩입니다. 그런데 이것들은 작동 방식이 근본적으로 다릅니다. 이 차이를 모르면 Claude Code를 "터미널에서 쓰는 Copilot" 정도로 오해하고, 실제로는 자동완성처럼 쓰다가 "생각보다 별로네"로 끝납니다.

    Part 1의 핵심은 그래서 딱 하나입니다. 왜 이것이 자동완성이 아닌가.

    개념 1 — 세 가지 사실로 보는 정의¶

    축 값 의미
    WHAT Agentic Tool 자율적으로 도구를 호출하며 멀티스텝 작업을 완수하는 에이전트형 도구
    WHERE Everywhere 터미널, VS Code, JetBrains, Desktop 앱, 웹, Slack까지 동일한 엔진
    WHO BY Anthropic Claude 모델을 만든 회사의 1차(first-party) 도구 → 모델 통합 깊이가 가장 깊음

    여기서 "1차 도구" 라는 표현이 중요합니다. Cursor나 Copilot은 남이 만든 모델을 가져다 쓰는 반면, Claude Code는 모델을 만든 회사가 그 모델에 맞춰 직접 설계한 도구입니다. 모델의 학습 방식과 도구 사용 규약이 처음부터 맞춰져 있다는 뜻입니다.

    • 최초 출시: 2024년
    • 현재 상태: GA (정식 출시)
    • 기본 주력 모델: Claude Sonnet 5

    Anthropic이라는 회사¶

    • 2021년 설립. 안전하고 신뢰 가능한 AI를 목표로 하는 프론티어 AI 기업
    • Constitutional AI 등 AI Safety 연구를 제품에 직접 반영하는 개발 철학
    • 제품군: Claude 모델 패밀리 / Claude Code / Agent SDK / Claude API / Claude 앱
    • AWS와 전략적 파트너십 — Amazon Bedrock에서 Claude 모델 제공

    개념 2 — Agentic AI란 무엇인가¶

    정의: Agentic AI는 사용자의 목표를 받아 스스로 계획을 세우고, 도구를 사용하며, 결과를 관찰하면서 목표 달성까지 자율적으로 작동하는 AI 시스템입니다.

    일반 챗봇은 "질문 → 답변"의 1회성 반응(Reactive)입니다. Agentic AI는 네 가지 속성이 추가됩니다.

    속성 설명
    Goal-driven (목표 주도) 단계별 명령이 아니라 최종 목표를 받아 스스로 경로를 결정
    Tool-using (도구 사용) 파일 읽기, 명령 실행, 웹 검색 등 외부 도구를 능동적으로 호출
    Observative (관찰) 도구 실행 결과를 관찰하고 다음 행동을 결정하는 피드백 루프
    Iterative (반복) 실패하면 다른 접근을 시도하며 완료까지 반복, 자가 수정

    Agentic Loop — 3단계¶

    작업을 하나 주면 Claude는 아래 세 단계를 섞어가며 수십 개의 행동을 연결합니다.

    ┌─────────────────────────────────────────────────────────┐
│                                                         │
│  ① Gather Context  →  ② Take Action  →  ③ Verify       │
│     컨텍스트 수집         도구로 실행         결과 검증      │
│     ・파일 검색/읽기      ・파일 편집         ・테스트 실행   │
│     ・CLAUDE.md 로드     ・명령 실행         ・타입 검사    │
│     ・메모리 로드         ・커밋            ・결과 관찰     │
│                                                         │
│          ↑                                    │         │
│          └──────────── Repeat / Steer ────────┘         │
│              완료까지 반복 · Esc로 언제든 개입              │
└─────────────────────────────────────────────────────────┘

    초보자가 놓치기 쉬운 포인트

    이 루프가 도는 동안 나는 구경만 하는 게 아닙니다. Esc 한 번으로 즉시 중단하고 방향을 바꿀 수 있습니다. "AI가 알아서 다 한다"가 아니라 "AI가 달리는 중에 내가 핸들을 잡을 수 있다" 가 정확한 그림입니다.

    개념 3 — Agentic Coding vs Code Completion¶

    이 표 하나가 Part 1의 결론입니다.

    Code Completion (기존 자동완성) Agentic Coding (Claude Code)
    컨텍스트 범위 현재 파일, 커서 주변 저장소 전체 + 터미널 + git 상태
    산출물 다음 몇 줄 제안 여러 파일 편집 + 명령 실행
    검증 주체 실행과 검증은 개발자 몫 테스트로 스스로 검증 후 수정
    동작 위치 IDE 안에서만 터미널, IDE, 웹 어디서든
    대표 예시 함수 시그니처 자동완성 실패 테스트 원인 추적과 수정

    다른 도구들과의 포지셔닝 (2026.07 기준)¶

    도구 특성 강점 영역
    Claude Code 터미널 중심 에이전트, 전 환경 확장, SDK 제공 저장소 단위 자율 작업
    GitHub Copilot IDE 자동완성에서 출발, 에이전트 기능 확장 중 IDE 내 코드 제안
    Cursor AI 네이티브 IDE, 에디터 경험 중심 IDE 통합 워크플로
    OpenAI Codex 클라우드 에이전트와 CLI 병행 위임형 클라우드 작업
    Gemini CLI Google 생태계 CLI 에이전트 GCP 연계 작업

    개념 4 — 모델 패밀리와 Alias¶

    Claude Code는 하나의 모델만 쓰는 게 아니라 작업 난이도에 따라 모델을 갈아탑니다.

    모델 특성 적합한 작업
    Claude Fable 5 최상위 Mythos-class, 장시간 자율 세션 특화 가장 어렵고 규모가 큰 작업
    Claude Opus 4.8 깊은 추론, 복잡한 아키텍처 결정 복잡한 리팩토링, 설계
    Claude Sonnet 5 기본 모델, 네이티브 1M 컨텍스트 일상 코딩 작업 전반
    Claude Haiku 4.5 빠른 응답, 비용 효율 간단한 변환, 검색, 분류
    • Sonnet 5 컨텍스트: 1M 토큰
    • 세션 중 전환: /model 명령
    • Sonnet 5는 v2.1.197+, Fable 5는 v2.1.170+ 필요

    Alias 시스템 — 버전 번호를 외우지 않아도 되는 이유¶

    모델 버전은 계속 바뀝니다. 그래서 버전 번호 대신 별칭(alias) 으로 지정합니다.

    Alias 해석 용도
    default 계정 유형별 권장 모델로 복귀하는 특수 값 오버라이드 해제
    best Fable 5 접근 가능하면 Fable 5, 아니면 최신 Opus 최고 성능 자동 선택
    fable / opus Fable 5 또는 최신 Opus 지정 난제, 장기 세션
    sonnet / haiku 최신 Sonnet 또는 Haiku 지정 일상 작업, 경량 작업
    opus[1m] 1M 토큰 컨텍스트 윈도우로 Opus 사용 초장기 세션
    opusplan Plan 모드는 opus, 실행은 sonnet으로 자동 전환 계획 품질과 실행 비용의 균형

    Tip

    opusplan은 실무에서 가장 가성비 좋은 선택지입니다. 어려운 건 "계획 세우기"이고 계획대로 코드를 치는 건 상대적으로 쉽기 때문에, 비싼 모델은 계획에만 쓰고 실행은 싼 모델에 맡기는 구조입니다.

    개념 5 — 어디서 실행되는가 (실행 환경 스펙트럼)¶

    "Use Claude Code Everywhere" — 표면은 6가지지만 엔진은 하나입니다.

    # 환경 특징
    1 Terminal CLI 모든 기능의 기준점. 파이프와 스크립트 등 Unix 조합성
    2 VS Code / Cursor 인라인 diff, @-mention, 플랜 검토를 에디터에서
    3 JetBrains IntelliJ, PyCharm 등에서 대화형 diff와 컨텍스트 공유
    4 Desktop App 병렬 세션, 시각적 diff, 예약 작업, 클라우드 세션 실행
    5 Web / iOS claude.ai/code에서 설치 없이 클라우드 실행, 모바일 연속 작업
    6 Slack / CI / Chrome @Claude 멘션, GitHub Actions, 라이브 웹앱 디버깅

    그런데 왜 터미널이 기준점인가¶

    이유 설명
    도구 접근성 빌드, git, 패키지 매니저 등 개발 도구가 모두 CLI에 존재
    조합 가능성 파이프, 리다이렉트, jq와 결합해 워크플로를 자유롭게 구성
    자동화 친화 -p 헤드리스 모드로 CI/CD와 스크립트에 즉시 통합
    IDE 중립 특정 에디터에 종속되지 않고 모든 개발 환경과 공존

    Unix 철학: 터미널에서 할 수 있는 모든 것을 Claude도 할 수 있습니다.

    개념 6 — 4대 핵심 가치¶

    가치 내용 키워드
    깊은 코드 이해 단일 파일이 아닌 프로젝트 전체를 자율 탐색하며 컨텍스트 구축 Repo-wide
    실제 작업 완수 제안에 그치지 않고 파일 수정, 테스트 실행, PR 생성까지 수행 End-to-end
    안전한 권한 모델 allow / ask / deny 규칙과 체크포인트로 동작 범위를 통제 Granular
    확장 가능한 통합 Skills, Subagents, MCP, Hooks, SDK로 워크플로에 맞춰 확장 SDK + MCP

    자율성 스펙트럼 — 권한 모드 4종¶

    Shift+Tab으로 순환합니다. 오른쪽으로 갈수록 자율성이 커지고 내 개입이 줄어듭니다.

    Plan  →  Default  →  Accept Edits  →  Auto
 낮음  ←──────── 자율성 ────────→  높음
    모드 동작
    Plan 소스 수정 없이 탐색과 계획만, 승인 후 실행
    Default 파일 편집과 셸 명령 전에 매번 질문
    Accept Edits 편집과 mkdir 등 파일 작업은 자동, 그 외는 질문
    Auto 백그라운드 안전 검사로 전 행동을 평가 (리서치 프리뷰)

    CI 등 비대화 환경에서는 --permission-mode 플래그와 사전 합의된 allow 규칙으로 운영합니다.

    개념 7 — 주요 사용 사례 6선¶

    # 사례 내용
    1 디버깅 에러 메시지로부터 원인을 추적하고 수정안을 제시·적용
    2 리팩토링 대규모 코드베이스의 일관된 패턴 변경과 구조 개선
    3 신기능 개발 요구사항으로부터 계획, 구현, 테스트까지 일괄 처리
    4 코드베이스 학습 낯선 프로젝트의 구조와 흐름을 자연어 대화로 학습
    5 테스트 작성 커버리지 갭 분석과 자동 테스트 생성, 실패 수정
    6 DevOps 자동화 셸 스크립트, IaC, CI/CD 파이프라인 작성과 점검

    사례 1 — 디버깅 (실제 흐름)¶

    $ npm test
# FAIL src/auth/session.test.ts
#     TypeError: Cannot read properties of undefined

$ claude "npm test가 실패해. 원인을 찾아 고치고 테스트가 통과하는지 확인해줘"

    Claude의 진행 순서: 1. 테스트를 실행해 실패 로그 확보 2. 스택트레이스에 나온 session.ts를 읽음 3. null 가드 누락을 확인하고 Edit 수행 4. npm test 재실행으로 통과 검증

    왜 이게 되는가: 에러 메시지가 곧 시작 컨텍스트이고, 스스로 테스트를 돌려 검증하며, 여러 파일에 걸친 원인도 추적하기 때문입니다. 수정 전 스냅샷이 남아 되돌리기도 가능합니다.

    사례 2 — 리팩토링¶

    > src/ 전체에서 콜백 스타일 fs 호출을 fs/promises 기반 async/await로 바꿔줘.
  변경 후 lint와 테스트로 검증해줘.
    1. Grep으로 fs.readFile( 등 호출 지점 수집
    2. 파일별 Edit, import 구문까지 일괄 정리
    3. npm run lint && npm test 실행
    4. 실패 지점 재수정 후 요약 보고

    규모의 이점: 수십 개 파일에 동일 규칙을 적용하고, import 정리 같은 부수 변경까지 포함하며, 린트·테스트로 회귀를 방지합니다. /diff로 전체 변경을 한눈에 검토합니다.

    데이터 보안 및 프라이버시¶

    신뢰 경계(Trust Boundary): 로컬 실행 시 코드는 내 머신에 있고, 모델 추론에 필요한 컨텍스트만 API로 전송됩니다. 전송 구간과 저장 구간 모두 암호화됩니다.

    구간 내용
    LOCAL 파일 접근과 명령 실행은 사용자 머신에서, 권한 규칙으로 통제
    TRANSIT API 통신은 TLS로 보호. 사내 프록시와 커스텀 CA도 지원
    CLOUD Bedrock 사용 시 트래픽이 AWS 계정 경계 안에서 처리
    CONTROL managed settings, 감사 로그, ZDR 옵션으로 정책 강제
    • 전송 구간: TLS
    • 저장 데이터: AES-256
    • ZDR (Zero Data Retention) 옵션 제공
    • Bedrock PrivateLink 경로로 VPC 내부 통신 가능

    Anthropic 데이터 사용 정책 요약¶

    항목 내용
    학습 사용 상업용 계정은 기본 미사용, 명시 동의 시에만 (Console·Bedrock 경로 포함)
    보존 기간 안전성 검토 목적의 제한적 보존. ZDR 계약 시 보존 없음
    인간 검토 약관 위반 의심 등 예외 상황에 한정, 자동화 시스템 우선
    제3자 공유 법적 의무(소환장 등) 외 없음
    암호화 TLS in transit, AES-256 at rest — 모든 경로 동일

    흔한 오해 / 함정¶

    오해 실제
    "터미널 도구니까 IDE 쓰면 못 쓴다" 동일 엔진이 VS Code·JetBrains·Desktop·웹에서 다 돕니다. 설정과 CLAUDE.md도 공유됩니다.
    "Node.js를 깔아야 한다" Native 설치는 단일 바이너리라 Node 불필요. npm 경로로 설치할 때만 Node 18+ 필요.
    "무료로 써볼 수 있다" Free 플랜은 Claude Code 미포함. 구독 또는 API 계정이 필요합니다.
    "내 코드가 학습에 쓰인다" 상업용 계정은 기본 미사용이며, 명시 동의 시에만 사용됩니다.
    "모델을 하나 골라야 한다" 세션 중 /model로 언제든 전환합니다. opusplan 같은 자동 배분 alias도 있습니다.

    정리¶

    • Claude Code는 Agentic Loop(수집 → 실행 → 검증 반복)로 저장소 단위 작업을 완수하는 Anthropic의 1차 도구입니다.
    • 자동완성과의 차이는 범위(파일 vs 저장소)와 책임(제안 vs 검증까지 완수)입니다.
    • 모델은 Fable 5 / Opus 4.8 / Sonnet 5 / Haiku 4.5이고, 버전 대신 alias로 지정합니다.
    • 실행 표면은 CLI, IDE, Desktop, Web, Slack까지 6종이지만 엔진과 설정은 하나입니다.
    • 코드는 로컬에 있고 컨텍스트만 전송되며, 상업용 계정은 기본적으로 학습에 사용되지 않습니다.
