    Part 7 — 인터페이스¶

    한 줄 요약¶

    표면은 달라도 엔진과 설정은 하나입니다. "무엇을 하고 싶은가"에서 출발해 표면을 고르고, 세션은 teleport와 remote로 환경 사이를 자유롭게 이동합니다.

    왜 알아야 하나¶

    Claude Code를 CLI 도구로만 알고 있으면 이런 상황에서 막힙니다.

    • "빌드가 40분 걸리는데 그동안 노트북을 못 닫는다"
    • "출근길에 어제 작업 진행 상황만 확인하고 싶다"
    • "슬랙에 올라온 버그 리포트를 그대로 작업으로 넘기고 싶다"

    이 문제들은 다른 표면을 쓰면 풀립니다. Part 7은 그 지도입니다.

    개념 1 — 인터페이스 선택 가이드¶

    원하는 것 → 최적 표면 매핑입니다. 이 표부터 보세요.

    원하는 것 표면 특징
    휴대폰에서 로컬 세션 이어가기 Remote Control 실행은 내 머신 유지
    로컬에서 시작, 모바일에서 계속 Web / iOS + Teleport 클라우드 세션 이동
    반복 일정으로 실행 Routines / Desktop 예약 머신 꺼져도 Routines
    PR 리뷰, 이슈 분류 자동화 GitHub Actions / GitLab CI 통합
    Slack 버그 리포트를 PR로 Slack 통합 @Claude 멘션
    라이브 웹앱 디버깅 Chrome 통합 콘솔, DOM 접근

    개념 2 — VS Code / Cursor 확장¶

    설치¶

    # 확장 마켓플레이스에서 'Claude Code' 검색
# Cmd+Shift+X (macOS) / Ctrl+Shift+X (Windows·Linux)

# 설치 후 실행
#   Cmd+Shift+P → 'Claude Code' → 'Open in New Tab' 선택

# Cursor도 같은 확장 사용
#   vscode:extension/anthropic.claude-code
#   cursor:extension/anthropic.claude-code

    요구사항: - Claude 구독 또는 서드파티 공급자 - CLI 설정과 CLAUDE.md를 그대로 공유 - MCP 서버 구성도 동일 적용 - 터미널 세션과 자유롭게 병행 가능

    주요 기능¶

    기능 내용
    인라인 Diff 제안 변경을 에디터 diff로 검토, 부분 수락 가능
    @-mentions @파일, @심볼로 컨텍스트를 정확히 지목해 전달
    Plan 검토 Plan 모드 산출물을 패널에서 구조적으로 검토
    대화 이력 세션 이력을 에디터 안에서 탐색하고 재개

    Tip

    CLI 대비 가장 큰 차이는 부분 수락입니다. 터미널에서는 diff를 통째로 y/n 하지만, 에디터에서는 원하는 hunk만 골라 받을 수 있습니다.

    개념 3 — JetBrains 플러그인¶

    Marketplace에서 Claude Code 플러그인을 설치하고 IDE를 재시작합니다. 별도로 설치된 CLI가 필요합니다.

    축 내용
    설치 요건 Marketplace 플러그인 + 별도 CLI 설치, 재시작
    대화형 Diff IDE diff 뷰어로 변경 검토와 수락
    선택 공유 에디터 선택 영역을 컨텍스트로 전달
    단축키 IDE 키맵 체계에 통합, 커스터마이즈 가능

    IntelliJ, PyCharm, WebStorm 등 IntelliJ 계열 전체를 지원합니다.

    개념 4 — Desktop 앱 (병렬 세션의 본진)¶

    IDE와 터미널 밖의 독립 앱입니다. 여러 세션을 git 격리로 나란히 돌리고, 시각적 diff와 앱 프리뷰, PR 모니터링까지 제공합니다.

    기능 내용
    PARALLEL — 병렬 세션 세션마다 git 격리, 드래그 앤 드롭 패널 배치
    VISUAL — 시각 검토 diff 검토, 앱 프리뷰, 통합 터미널과 파일 에디터
    DISPATCH 휴대폰에서 작업을 보내면 데스크톱 세션으로 생성
    CLOUD 로컬과 클라우드 세션을 한 화면에서 함께 운영
    • macOS / Windows 지원, Linux는 베타
    • /desktop — CLI 세션을 데스크톱으로 이관하는 명령
    • 세션별 워크트리로 격리
    • PR 모니터링 기능 내장

    예약 실행 두 경로 — Desktop 예약 vs Routines¶

    로컬 파일이 필요하면 Desktop 예약, 머신이 꺼져도 돌아야 하면 Routines입니다.

    Desktop Scheduled Tasks Routines (claude.ai)
    내 머신에서 실행 Anthropic 관리 인프라에서 실행
    로컬 파일과 도구에 직접 접근 머신 꺼져도 스케줄 유지
    아침 코드리뷰, 야간 감사 등 API 호출과 GitHub 이벤트 트리거
    머신이 켜져 있어야 동작 /schedule로 CLI에서도 생성

    개념 5 — Web (claude.ai/code)¶

    브라우저에서 GitHub 저장소를 연결해 클라우드 세션을 시작합니다. 장시간 작업을 걸어두고 나중에 확인하거나, 여러 작업을 병렬로 돌립니다.

    축 내용
    START claude.ai/code 접속 → 저장소 연결 → 작업 제출
    ENV Anthropic 샌드박스 VM, 셋업 스크립트와 네트워크 설정
    MOBILE iOS 앱에서 같은 세션 관리, 이동 중 진행 확인
    AUTOFIX /autofix-pr로 CI 실패와 리뷰 코멘트에 자동 대응

    결과는 PR로 회수됩니다. 즉 "작업을 던져두면 PR이 와 있는" 워크플로입니다.

    개념 6 — Teleport와 Remote Control (세션 이동)¶

    세 명령의 방향이 다릅니다. 헷갈리기 쉬우니 화살표로 기억하세요.

    # 웹·iOS에서 시작한 세션을 터미널로 가져오기   (클라우드 → 로컬)
claude --teleport
# 목록에서 클라우드 세션 선택, 로컬로 이어서 작업

# 터미널 세션을 클라우드로 보내기              (로컬 → 클라우드)
claude --remote "이 작업 계속 진행해줘"

    # 로컬 세션을 폰·브라우저에서 조종            (실행은 로컬, 조작만 원격)
> /remote-control
# claude.ai/code 또는 모바일 앱에서 접속
    명령 방향 실행 위치
    --teleport 클라우드 → 로컬 로컬
    --remote 로컬 → 클라우드 클라우드
    /remote-control 조작만 원격 로컬 유지

    claude.ai 연동 기능이므로 구독이 필요합니다.

    개념 7 — Slack 통합¶

    채널에서 @Claude를 멘션해 작업을 위임합니다. 버그 리포트 스레드가 그대로 컨텍스트가 되고, 결과는 PR로 돌아옵니다.

    축 내용
    TRIGGER 채널과 스레드에서 @Claude 멘션으로 작업 시작
    CONTEXT 리포트 대화 내용이 작업 배경으로 전달
    OUTPUT 수정 결과를 PR 링크로 스레드에 회신
    OPS 버그 트리아지, 온콜 보조, 질문 응대 자동화

    Tip

    운영 관점에서 가장 실용적인 지점은 온콜 보조입니다. 장애 스레드에서 바로 로그 분석을 위임하고, 스레드 맥락이 그대로 컨텍스트가 되므로 상황 설명을 다시 쓸 필요가 없습니다.

    개념 8 — Chrome 통합 (Beta)¶

    Chrome 브라우저에 연결해 실제 페이지를 조작합니다. 콘솔 로그를 읽고, 폼을 채우고, DOM을 검사하며 프론트엔드를 디버깅합니다.

    축 내용
    DEBUG 콘솔 에러와 네트워크 요청을 읽어 원인 추적
    TEST 구현한 UI를 실제로 클릭하고 입력해 확인
    AUTOMATE 반복 입력과 데이터 추출 작업 수행
    SETUP 확장 설치 후 /chrome으로 연결 설정

    개념 9 — 터미널 환경 최적화¶

    CLI 사용감을 크게 올려주는 설정들입니다. 처음 설치했으면 이건 꼭 하세요.

    항목 방법 왜 필요한가
    Shift+Enter 줄바꿈 terminal-config 절차로 키 매핑 멀티라인 프롬프트 필수
    완료 알림 벨 터미널 벨 설정으로 종료 신호 장시간 작업을 백그라운드화
    Vim 모드 /config에서 편집 키 바인딩 전환 Vim 사용자 이질감 제거
    풀스크린 렌더링 깜빡임 없는 렌더링, 마우스 지원 /focus 뷰 사용 가능
    상태줄 statusline으로 컨텍스트·비용·git 표시 세션 상황 상시 노출

    Tip

    Shift+Enter 매핑을 안 하면 여러 줄 프롬프트를 쓸 수가 없어서 지시가 계속 짧고 모호해집니다. Part 5에서 강조한 "구체적 지시"의 물리적 전제조건입니다.

    개념 10 — 키보드 단축키 종합¶

    키 동작 비고
    Esc / Esc Esc 즉시 중단 / 체크포인트 되감기 가장 자주 쓰는 두 동작
    Shift+Tab 권한 모드 순환 Plan 진입은 두 번
    Ctrl+R 전 프로젝트 명령 이력 검색 과거 프롬프트 재사용
    / 입력 명령 자동완성 필터 명령 탐색 기본기
    ! 접두 셸 모드 직접 실행, 출력에 응답 빠른 셸 확인
    c (로그인 시) 로그인 URL 클립보드 복사 브라우저 미개방 환경

    정리¶

    • 표면은 CLI / VS Code·Cursor / JetBrains / Desktop / Web·iOS / Slack / Chrome 이지만 엔진과 설정은 하나입니다.
    • 에디터 확장의 차별점은 인라인 diff의 부분 수락과 @-mention 컨텍스트 지목입니다.
    • Desktop 앱은 병렬 세션 + git 격리가 핵심이고, 예약 작업은 로컬(Desktop) vs 관리형(Routines)으로 갈립니다.
    • 세션 이동 세 명령: --teleport(클라우드→로컬), --remote(로컬→클라우드), /remote-control(조작만 원격).
    • 터미널을 쓴다면 Shift+Enter 줄바꿈 매핑과 상태줄 설정은 초기에 반드시 하세요.
