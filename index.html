    Claude Code 완전 정복¶

    터미널에서 도는 AI 코딩 에이전트, Claude Code를 처음부터 끝까지.

    Claude Code를 한 번도 써본 적 없어도 이 문서만 읽고 설명할 수 있고, 설치해서 첫 세션을 돌릴 수 있는 상태가 되는 것을 목표로 정리했습니다.

    이 기록에 대하여¶

    저는 지금 가시다 스터디의 6주 모각코 과정을 따라가며 Claude Code를 학습하고 있습니다. AWS 최우형 SA가 만든 워크샵 교재(6챕터·900여 슬라이드)를 매주 한 챕터씩 읽고, 그 내용을 여기에 다시 씁니다.

    교재를 요약하는 것만으로는 남는 게 적다고 생각해서 두 가지를 더 했습니다.

    첫째, Claude Code를 배우면서 Claude Code로 작업했습니다. 실습은 물론이고 문서를 정리하는 과정 자체를 AI와 함께 진행했는데, 그러다 보니 교재에서 읽은 개념이 실제로는 어떻게 동작하는지가 자연스럽게 드러났습니다. "문서에는 이렇게 쓰여 있는데 실제로는 달랐다"는 발견이 계속 나왔고, 그 간극을 그대로 기록했습니다.

    둘째, 모든 실습을 진짜로 실행했습니다. 명령을 옮겨 적는 대신 직접 돌리고 출력을 그대로 붙였습니다. 그래서 이 문서에는 성공한 기록만 있는 게 아니라, 예상과 달랐던 것과 제가 잘못 알고 있었던 것도 함께 남아 있습니다.

    최종 목적지는 사내 스터디 자료입니다¶

    개인 학습 노트로 끝낼 생각은 없습니다. 이 6주가 끝나면 사내에서 Claude Code 스터디를 열 때 그대로 쓸 수 있는 교육 자료로 다듬는 것이 목표입니다.

    그래서 처음부터 "내가 나중에 다시 볼 메모"가 아니라 "Claude Code를 처음 접하는 동료가 이 문서만 보고 따라올 수 있는가" 를 기준으로 썼습니다. 용어는 처음 나올 때 풀어 쓰고, 결론보다 그렇게 설계된 이유를 먼저 적고, 표로 압축하기보다 서술로 풀었습니다. 분량이 늘어난 건 그 때문입니다.

    인프라를 다루는 일을 하다 보니 자연스럽게 그쪽 관점이 섞였습니다. Bedrock 인증 경로, IAM 최소 권한, 폐쇄망과 프록시, 조직 단위 버전 통제 같은 것들은 💡 현장 메모로 따로 표시해 두었습니다. 사내 도입을 검토할 때 필요한 이야기들입니다.

    30초로 보는 Claude Code¶

    자동완성 도구와 Claude Code의 차이는 딱 한 문장입니다.

    자동완성은 다음 몇 줄을 제안하고, Claude Code는 목표를 받아 저장소 전체에서 작업을 끝냅니다.

    파일을 스스로 찾아 읽고, 고치고, 테스트를 돌려 통과하는지 확인하고, 실패하면 다시 고칩니다.

    flowchart LR
    A["① Gather Context<br/>파일 검색·읽기<br/>CLAUDE.md 로드"] --> B["② Take Action<br/>파일 편집<br/>명령 실행"]
    B --> C["③ Verify Results<br/>테스트 실행<br/>결과 검증"]
    C -->|완료까지 반복| A
    C --> D(["완료"])
    style A fill:#ede7f6,stroke:#673ab7,color:#000
    style B fill:#e3f2fd,stroke:#1976d2,color:#000
    style C fill:#e8f5e9,stroke:#388e3c,color:#000
    style D fill:#fff3e0,stroke:#f57c00,color:#000

    이 반복을 Agentic Loop라 하고, 이 루프를 돌 수 있도록 모델 주위에 씌운 껍데기를 하네스(Harness) 라고 부릅니다.

    이 정리의 원칙¶

    • 검증된 출처만

      1차 출처는 워크샵 교재 PDF, 2차 출처는 Anthropic 공식 문서입니다. 추측이나 미확인 출처는 본문에 넣지 않고, 모든 문서 하단에 출처를 명시합니다.

    • 출력은 편집하지 않는다

      실행 환경(OS·버전·날짜)을 함께 남기고, 명령의 출력은 다듬지 않고 그대로 옮깁니다. 보기 좋게 정리하는 순간 재현할 수 없는 기록이 되기 때문입니다.

    • 못 한 건 "미완"으로

      수행하지 못한 실습은 했다고 쓰지 않습니다. 이유와 언제 할지를 함께 남깁니다.

    • 교재와 실제가 다르면 적는다

      문서에 없던 필드, 존재하지 않는 경로, 예상과 달랐던 동작 — 직접 해봐야만 알 수 있는 것을 남기는 게 이 정리의 목적입니다.
