    Claude Code Deep Dive — 6주 학습 기록¶

    도구의 원리부터 조직 운영, 자동화, Agent SDK까지 직접 실행하며 확인한 기록입니다.

    Claude Code를 처음 접한 사람도 기본 개념에서 출발해 서브에이전트, 조직 설정, 자동화, SDK 기반 에이전트 개발까지 단계적으로 따라갈 수 있도록 6주 과정을 한 흐름으로 정리했습니다.

    이 기록에 대하여¶

    저는 서종호님이 진행하는 가시다 스터디의 6주 모각코 과정을 따라 Claude Code를 학습했습니다. AWS 최우형 SA가 만든 워크샵 교재(6챕터·900여 슬라이드)를 매주 한 챕터씩 읽고, 직접 실행해 확인한 내용을 여기에 다시 썼습니다.

    교재를 요약하는 것만으로는 남는 게 적을 것 같아서, Claude Code를 배우는 과정 자체를 Claude Code로 진행하고 그 기록을 남기는 방식으로 정리했습니다.

    그러다 보니 교재에서 읽은 개념이 실제로는 어떻게 동작하는지가 계속 드러났습니다. 문서에는 이렇게 쓰여 있는데 돌려보니 다른 경우가 있었고, 제가 잘못 이해하고 있던 것도 나왔습니다. 그런 간극을 지우지 않고 그대로 적었습니다.

    그래서 이 문서의 실습 부분은 교재의 명령을 옮겨 적은 것이 아니라 실제로 실행된 출력입니다. 실행 환경과 날짜를 함께 남겼고, 결과는 다듬지 않았습니다. 잘 된 것뿐 아니라 예상과 달랐던 것, 수행하지 못한 것도 그대로 두었습니다.

    최종 목적지는 사내 스터디 자료입니다¶

    개인 학습 노트로 끝낼 생각은 없습니다. 6주 과정을 마친 뒤에도 사내에서 Claude Code 스터디를 열 때 그대로 쓸 수 있는 교육 자료가 되도록 구성했습니다.

    그래서 처음부터 "내가 나중에 다시 볼 메모"가 아니라 "Claude Code를 처음 접하는 동료가 이 문서만 보고 따라올 수 있는가" 를 기준으로 썼습니다. 용어는 처음 나올 때 풀어 쓰고, 결론보다 그렇게 설계된 이유를 먼저 적고, 표로 압축하기보다 서술로 풀었습니다. 분량이 늘어난 건 그 때문입니다.

    30초로 보는 Claude Code¶

    자동완성 도구와 Claude Code의 차이는 딱 한 문장입니다.

    자동완성은 다음 몇 줄을 제안하고, Claude Code는 목표를 받아 저장소 전체에서 작업을 끝냅니다.

    파일을 스스로 찾아 읽고, 고치고, 테스트를 돌려 통과하는지 확인하고, 실패하면 다시 고칩니다.

    flowchart LR
    A["① Gather Context<br/>파일 검색·읽기<br/>CLAUDE.md 로드"] --> B["② Take Action<br/>파일 편집<br/>명령 실행"]
    B --> C["③ Verify Results<br/>테스트 실행<br/>결과 검증"]
    C -->|완료까지 반복| A
    C --> D(["완료"])

    이 반복을 Agentic Loop라 하고, 이 루프를 돌 수 있도록 모델 주위에 씌운 껍데기를 하네스(Harness) 라고 부릅니다.

    6주가 어떻게 이어지는가¶

    • 1주차 — 도구를 이해하고 직접 써보기

      Claude Code가 자동완성과 무엇이 다른지 이해하고 설치·인증·첫 세션·핵심 워크플로를 익힙니다.

      Chapter 1 — Overview

    • 2주차 — 일을 나누고 품질 높이기

      무거운 작업을 격리 컨텍스트의 Subagent에 위임하고, 리뷰·테스트·보안·문서화 패턴으로 조합합니다.

      Chapter 2 — Agents

    • 3주차 — 개인 도구를 조직 플랫폼으로 바꾸기

      대규모 배포, SSO·임시 자격증명, 네트워크, 정책 강제, 관측과 컴플라이언스를 다룹니다.

      Chapter 3 — Admin Setup

    • 4주차 — 동작 범위를 설정으로 통제하기

      설정 스코프와 권한 규칙을 이해하고 Hooks·MCP·Commands·Skills를 하나의 확장 체계로 연결합니다.

      Chapter 4 — Settings

    • 5주차 — 대화를 운영 가능한 자동화로 바꾸기

      Headless 실행의 입력·출력·실패 계약을 익히고 세션, 스케줄, CI/CD, 비용 상한을 코드로 통제합니다.

      Chapter 5 — CLI Reference

    • 6주차 — 에이전트를 프로그램 안에 넣기

      Agent SDK의 query()에서 시작해 멀티턴, 커스텀 도구, 구조화 출력, 권한, 세션과 배포 경계를 조립합니다.

      Chapter 6 — Agent SDK

    이 정리의 원칙¶

    • 검증된 출처만

      1차 출처는 워크샵 교재 PDF, 2차 출처는 Anthropic 공식 문서입니다. 추측이나 미확인 출처는 본문에 넣지 않고, 모든 문서 하단에 출처를 명시합니다.

    • 출력은 편집하지 않는다

      실행 환경(OS·버전·날짜)을 함께 남기고, 명령의 출력은 다듬지 않고 그대로 옮깁니다. 보기 좋게 정리하는 순간 재현할 수 없는 기록이 되기 때문입니다.

    • 못 한 건 "미완"으로

      수행하지 못한 실습은 했다고 쓰지 않습니다. 이유와 언제 할지를 함께 남깁니다.

    • 교재와 실제가 다르면 적는다

      문서에 없던 필드, 존재하지 않는 경로, 예상과 달랐던 동작 — 직접 해봐야만 알 수 있는 것을 남기는 게 이 정리의 목적입니다.
