    Part 1 — SDK 기본¶

    한 줄 요약¶

    Agent SDK는 터미널에서 쓰던 Claude Code를 코드 몇 줄로 호출하고 그 답을 프로그램이 받아쓸 수 있게 해주는 라이브러리입니다.

    왜 알아야 하나¶

    claude -p로 받은 답을 셸에서 if로 분기하거나 다음 질문에 이어 붙이려는 순간, 문자열 이스케이프와 파싱이 발목을 잡습니다. 프로그램이 그 답을 코드의 값으로 직접 받아 분기하고 다음 호출에 그대로 넘길 수 있다면 이 문제가 사라집니다 — Agent SDK가 하는 일이 정확히 이겁니다. 터미널에서 claude -p가 잘 되는데 서비스 코드에서 같은 일을 하려면 API 요청·도구 루프·권한 처리를 새로 만들어야 한다고 생각하기 쉽습니다. 하지만 SDK는 이미 완성된 실력(모델 호출·도구 실행·세션 기록을 묶어 도는 CLI 하네스)은 그대로 두고 그걸 부르는 방법과 답을 받아쓰는 방법만 코드로 옮기는 것에 가깝습니다.

    (2주차에서 서브에이전트를 "오늘 처음 출근한 신입 인턴"에 비유했습니다 — 지시서와 회사 규정은 받지만 팀장이 지금까지 나눈 대화는 전혀 모른 채 시작하는 인턴이었습니다. 이번 주 SDK는 그 이야기의 다음 장입니다: 그 인턴이 이제 정식 사원으로 채용되어 우리 프로그램이 코드로 직접 호출할 수 있는 시스템 구성원이 된 셈입니다.)

    코드를 읽기 전에¶

    이 챕터부터는 JavaScript 코드가 계속 나옵니다. 개발 경험이 없어도 아래 여섯 가지만 알아두면 코드를 따라 읽을 수 있습니다.

    • import — 설치해 둔 패키지에서 필요한 기능만 이름으로 꺼내 쓰는 선언입니다. import { query } from "패키지명"은 그 패키지 안의 query라는 기능 하나를 가져오는 것입니다. (Node.js는 터미널에서 JavaScript를 실행해주는 프로그램이고 npm은 그 패키지를 설치·관리하는 도구입니다 — 리눅스의 apt/yum과 같은 역할입니다.)
    • { 키: 값 }(객체) — JSON과 같은 키-값 묶음입니다. options: { allowedTools: [...], maxTurns: 3 }은 options라는 이름 아래 여러 설정값을 한데 묶어 넣은 것입니다.
    • await / for await — await는 "결과가 올 때까지 기다렸다가 다음 줄로 넘어간다"는 뜻입니다. for await는 상대가 한 번에 다 주지 않고 한 조각씩 순서대로 보내줄 때, 도착하는 대로 하나씩 받아 처리하는 반복문입니다.
    • 콜백 — "이런 상황이 오면 이 함수를 대신 불러줘"라고 미리 맡겨두는 함수입니다. CloudWatch 알람에 걸어둔 Lambda처럼, 우리가 직접 부르는 게 아니라 SDK가 필요할 때 대신 불러줍니다. Part 5에서 자세히 다룹니다.
    • Promise — "지금은 값이 없지만 나중에 줄게"라는 영수증입니다. await는 그 영수증을 실제 값으로 바꿔 받는 동작입니다.
    • 예외(throw) — 함수가 "정상적으로 끝내지 못했다"며 실행을 그 자리에서 멈추는 신호입니다. 잡아주는 코드(catch)가 없으면 프로그램이 죽습니다 — 셸 스크립트의 set -e와 비슷합니다. Part 3에서 다룹니다.

    1. 가장 작은 예제부터 봅니다¶

    SDK를 쓴 코드는 생각보다 짧습니다. 아래가 전부입니다. (이 정리의 코드는 TypeScript의 타입 표기를 뺀 순수 JavaScript로, .mjs 파일에 저장해 node 명령으로 바로 실행합니다 — 6주차 목차의 "30초 요약"에 나온 "TypeScript와 Python에서 호출"은 SDK가 지원하는 언어 선택지를 말하는 것이고 여기서는 그중 자바스크립트 쪽 문법을 씁니다.)

    import { query } from "@anthropic-ai/claude-agent-sdk";

const q = query({
  prompt: "이 디렉터리의 파일 목록을 보고 한 줄 소감을 말해줘",
  options: { allowedTools: ["Read", "Glob"], maxTurns: 3 },
});

for await (const m of q) {
  if (m.type === "assistant") {
    for (const b of m.message.content) if (b.type === "text") process.stdout.write(b.text);
  }
  if (m.type === "result") {
    console.log(`\n--- session=${m.session_id} turns=${m.num_turns} cost=$${m.total_cost_usd}`);
  }
}

    실제로 실행하면 이렇게 나옵니다.

    $ node hello.mjs
Codex 관련 실험용 스크립트(.mjs)들과 로그, 문서가 뒤섞여 있는 걸 보니 API 연동을 이것저것 테스트해보던 작업 디렉토리네요.
--- session=7ebab039-860c-4927-9694-3525e14adbd7 turns=2 cost=$0.1208436

    query()를 부르면 코드 뒤에서 claude 프로그램이 하나 더 실행됩니다 — 이게 "자식 프로세스로 실행한다"는 말의 실체입니다. 우리 코드는 그 프로그램이 순서대로 흘려보내는 메시지를 for await로 하나씩 받습니다. 위 실행에는 두 종류만 나왔습니다: 모델이 쓴 문장을 담은 assistant 메시지, 그리고 끝났을 때 session ID·턴 수·비용을 담은 result 메시지입니다. "메시지 스트림을 읽는다"는 말은 결국 이 for await 루프를 가리킵니다. (system·user 메시지도 있는데, 대화가 길어지거나 도구를 쓸 때 등장합니다 — Part 2에서 다룹니다.) 코드 안의 m.type === "assistant"는 "메시지 종류가 assistant와 같은가"를 묻는 비교입니다. 그 안의 for (const b of m.message.content)는 메시지 하나에 여러 조각(글자·도구 호출 등)이 목록으로 들어 있어 그중 글자 조각만 골라내는 반복문입니다.

    여기서 session ID는 다음 질문을 이어갈 좌표이고 turns와 cost는 호출 한 번의 관측값입니다. m.result처럼 최종 문자열만 꺼내 저장하면 이 세 값은 사라집니다.

    2. 이 코드를 실제로 돌리려면¶

    랩 원문은 Node.js 프로젝트에 SDK와 Zod를 설치한 뒤 claude /status로 인증을 확인하라고 안내합니다. 이 환경에서는 실제 결과가 달랐습니다.

    $ node -v
v25.8.1
$ npm install @anthropic-ai/claude-agent-sdk zod
npm error Your cache folder contains root-owned files
$ npm install --cache ./npm-cache @anthropic-ai/claude-agent-sdk zod
$ npm ls @anthropic-ai/claude-agent-sdk zod
@anthropic-ai/claude-agent-sdk@0.3.260
zod@4.5.4
$ claude /status
/status isn't available in this environment.

    기본 npm 캐시에는 이 계정이 쓸 수 없는 파일이 들어 있었습니다. 패키지나 인증 문제로 단정하지 않고 프로젝트 안의 캐시를 지정해 설치를 마쳤습니다. /status 실패도 로그아웃의 증거는 아니었습니다. 바로 위 hello.mjs가 기존 CLI 로그인으로 모델을 호출했기 때문입니다.

    여기서 새 자격증명을 따로 만들지 않았다는 점이 중요합니다. SDK는 시스템에 설치된 claude 명령을 그대로 부르는 게 아니라 패키지가 플랫폼별로 따로 받아오는 바이너리(예: @anthropic-ai/claude-agent-sdk-darwin-arm64)를 실행합니다. 다만 인증 정보는 ~/.claude의 로그인을 그대로 읽으므로 이미 claude CLI에 로그인돼 있으면 SDK도 별도 설정 없이 같은 계정으로 동작합니다.

    버전 드리프트가 아니라 실행 모드 제약

    claude /status는 대화형 TUI 전용 슬래시 명령이라 비대화형 실행에서는 막힙니다(로컬에서 claude -p "/status"를 돌려도 같은 메시지가 뜹니다). 비대화형으로 인증을 확인하려면 로그인 여부와 인증 방식을 JSON으로 돌려주는 claude auth status가 더 정확합니다. 랩 원문의 /status 안내는 대화형 셸을 전제한 것이라 스크립트로 돌리는 이 실습 방식과는 애초에 안 맞았던 셈입니다.

    3. options는 이 호출의 규칙입니다¶

    위 코드의 options: { allowedTools: ["Read", "Glob"], maxTurns: 3 }을 다시 봅시다. 이 두 줄이 "인턴에게 무엇을 허락하고 어디서 멈출지"를 정하는 부분입니다.

    allowedTools는 화이트리스트처럼 보이지만 실제로는 "승인 없이 바로 실행되는 도구" 목록일 뿐입니다. 여기 없는 도구(Bash 포함)도 모델에게는 여전히 보이고 모델이 호출을 시도하면 권한 모드로 넘어가 승인 콜백이 없는 한 거부됩니다 — 즉 이 예제에서 Bash가 안 도는 건 "안 보여서"가 아니라 "시도했다가 거부당해서"입니다. 도구 자체를 안 보이게 하려면 tools나 disallowedTools로 따로 제한해야 하고 bypassPermissions 모드에서는 이 목록 자체가 무시됩니다.

    maxTurns는 도구를 실제로 호출한 왕복 수만 셉니다 — 텍스트만 오간 마지막 턴은 포함되지 않습니다. 작은 확인 작업에 상한을 먼저 둬야 예상보다 긴 탐색이 비용으로 번지지 않습니다.

    흔한 오해 바로잡기¶

    "allowedTools에 없는 도구는 모델에게 아예 안 보인다" — 아닙니다. 위에서 확인했듯 Bash는 여전히 모델 눈에 보이고 모델이 호출을 시도하면 승인 콜백이 없어 그 자리에서 거부됩니다. 도구 자체를 감추고 싶다면 tools나 disallowedTools로 따로 제한해야 합니다.

    "SDK 실습이 잘 됐으니 이 인증(구독 로그인 상속)을 그대로 서비스에 써도 된다" — 아닙니다. 로컬 개발 환경에서는 통하지만 공식 문서는 claude.ai 로그인을 제품·서비스에 얹는 걸 사전 승인 없이는 금지합니다. 실제로 배포한다면 ANTHROPIC_API_KEY나 Bedrock·Vertex·Foundry로 인증 경로를 바꿔야 합니다(Part 7에서 이어집니다).

    정리¶

    정리하면 셋입니다. ① SDK는 claude를 대신할 새 엔진이 아니라 코드 뒤에서 그 프로그램을 그대로 부르고 메시지를 받아쓰는 방식입니다. ② 이미 로그인돼 있으면 별도 자격증명 없이 동작하지만 이건 로컬 개발용 지름길이고 실제 서비스에는 API 키나 Bedrock 같은 다른 인증 경로가 필요합니다. ③ options는 장식이 아니라 "무엇을 허락하고 어디서 멈출지"를 코드로 못 박는 자리입니다. 다음 파트부터는 이 자리에 도구·출력·권한·세션이 하나씩 추가됩니다.
