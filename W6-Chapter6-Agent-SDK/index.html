    6주차 — Chapter 6: Agent SDK¶

    5주차에서는 claude -p를 셸에 엮어 자동화했습니다. 그런데 그 답으로 다음 질문을 이어가거나, 프로그램이 값으로 직접 분기하거나, 도구를 코드로 쥐여주려는 순간 셸 문자열 처리로는 한계에 부딪힙니다. 이번 주는 그 지점을 SDK로 코드 안에서 직접 풀어본 기록입니다. 실제로 돌려보니 Zod가 만든 스키마가 draft/2020-12 형식이라 거부되고 maxTurns: 4가 실제로는 부족해 상한에 걸리는 걸 그대로 겪었습니다. Agent SDK는 이 문제들을 코드 몇 줄로 다루게 해주는 라이브러리입니다. query() 하나로 시작해 대화 재개, in-process MCP 도구, 출력 계약, 권한 관문까지 차례로 붙여봤습니다.

    원본: Claude Code Deep Dive Workshop / Chapter 6 — Agent SDK (9파트, 약 84 슬라이드) 기준 버전: Claude Code 2.1.260 / @anthropic-ai/claude-agent-sdk 0.3.260 / 2026-09-04 · 교재는 2026년 7월판

    회고¶

    첫 hello.mjs는 생각보다 평범했습니다. 파일 목록을 읽어 한 줄을 답하고 마지막 메시지에 session ID와 비용을 붙여 보냈습니다. CLI를 라이브러리로 바꾼다고 해서 모델 호출을 처음부터 조립하는 게 아니라는 점이 여기서 분명해졌습니다. 인증, 도구 실행, 세션 기록은 이미 Claude Code 쪽에 있고 프로그램은 그 흐름을 순회할 뿐이었습니다.

    랩을 그대로 따라가자 교재 시점과 현재 버전의 틈도 바로 드러났습니다. claude /status는 이 실행 환경에서 사용할 수 없었지만 SDK의 첫 query는 기존 CLI 인증으로 성공했습니다. 더 큰 차이는 settingSources였습니다. 랩은 생략하면 파일시스템 설정을 읽지 않는다고 설명하는데, 현재 타입 선언과 공식 문서는 생략 시 user·project·local을 모두 읽는다고 명시하고 있었습니다. 임베딩 프로그램에서 예측 가능한 실행을 원한다면 이제 []를 직접 적어야 합니다.

    세션 랩은 더 조심스럽게 읽게 됐습니다. 대화 재개는 sessionId를 갱신해 resume에 넘기는 세 줄로 실제로 이어졌지만, 상태 파일 점검원은 랩 원문의 maxTurns: 4로는 상한에 걸려 죽었습니다. 성공 예시만 옮기지 않고 이 실패를 먼저 남긴 이유입니다. 상한을 8로 올려 다시 돌리자 OK→DOWN 상태 변화까지 정확히 잡아냈습니다 — 상한은 설명용 숫자가 아니라 실제 프롬프트와 모델을 넣어 직접 재봐야 하는 운영값이었습니다.

    6주를 마치며 남은 감각은 단순합니다. 좋은 에이전트는 프롬프트 한 줄에서 나오지 않습니다. 입력의 범위, 출력의 계약, 도구의 권한, 세션의 보존 위치가 코드에서 보일 때 비로소 다음 사람이 고칠 수 있는 프로그램이 됩니다.

    30초 요약¶

    SDK는 Claude Code의 대화·도구·권한·세션 기능을 TypeScript와 Python에서 호출하는 표면입니다. query()의 메시지 스트림을 읽고 필요한 곳에 도구와 정책을 붙입니다.

    가장 먼저 실행 가능한 query를 만들고 그다음에 JSON Schema로 출력 모양을 고정합니다. 쓰기 같은 위험한 도구는 canUseTool 또는 PreToolUse 훅으로 통제합니다. 세션 ID는 메모리 안에서는 대화를 잇고, 파일·DB에 저장하면 프로세스가 바뀌어도 이력을 잇습니다.

    시작하기 전에 확인할 것¶

    Node.js 18 이상과 Claude Code 로그인이 필요합니다. 이 랩은 별도 API 키를 만들지 않고 SDK가 Claude Code 프로세스를 실행해 기존 로그인을 그대로 씁니다 — 다만 이건 로컬 개발용 지름길입니다. 공식 문서는 claude.ai 구독 로그인을 제품·서비스에 얹는 걸 사전 승인 없이는 금지하고 지원 인증 경로로 ANTHROPIC_API_KEY·Bedrock·Vertex·Foundry만 명시합니다(Part 1·Part 7 참고). claude /status처럼 대화형 UI 명령은 실행 환경에 따라 사용할 수 없습니다. 인증의 진짜 확인은 작은 query()가 result 메시지를 돌려주는지입니다.

    SDK는 기본 설정을 상속할 수 있습니다. 로컬의 CLAUDE.md나 MCP 설정이 몰래 실행을 바꾸지 않게 하려면 settingSources: []를 적고 의도적으로 프로젝트 설정을 쓸 때만 ['project']를 넣습니다.

    이 정리의 실습은 2026-09-04에 직접 실행한 결과입니다. 환경: macOS 26.6.2 / Node 25.8.1 / Claude Code 2.1.260 / SDK 0.3.260 / Zod 4.5.4.

    Lab 상태 핵심 발견
    Task 0 — 설치·인증 ⚠️ 부분 완료 npm 기본 캐시는 root 소유 파일로 실패했고, 프로젝트 전용 캐시로 설치했습니다. /status는 이 환경에서 미지원이었습니다.
    Task 1 — 첫 query ✅ 완료 기존 CLI 인증으로 query 성공, 2턴·$0.1208436을 기록했습니다.
    Task 2 — 대화 메모리 ✅ 완료 resume에 넘긴 session_id로 두 번째 질문이 이름을 정확히 기억했습니다.
    Task 3 — 커스텀 도구 ✅ 완료 in-process MCP의 노트 검색과 금요일 배포 규칙을 확인했습니다.
    Task 4 — 점검원 ✅ 완료 랩의 maxTurns: 4는 부족해 상한에 걸렸고, 8로 올리자 OK→DOWN 상태 변화까지 정확히 잡아냈습니다.
